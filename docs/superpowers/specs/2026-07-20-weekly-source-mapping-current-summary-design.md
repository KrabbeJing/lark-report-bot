# 日报事实字段级合并与周报来源映射设计

## 文档定位

本设计统一以下已确认口径：

- 表单日报与群聊日报按业务字段合并，不再整条记录按时间互相覆盖。
- 团队通讯录只维护人员身份、所属板块和日报汇报关系，不维护敏捷小组、分管领导或人员类型。
- 日报统一事实表不再保存敏捷小组。
- 模块二和模块三按独立的周报来源映射和业务规则归集，且同一日报事项只能进入一个周报目标。
- 周报事实周期为上周五至本周四闭区间。
- 只生成模块二“本周重点事项说明”和模块三“本周工作进展”。
- 周五 16:30 首次生成，17:00 私聊周报负责人；周六 09:30 安全刷新，11:00 生成并发送海报。
- 不展示日报覆盖率、缺报人员、人员类型或敏捷小组身份。

本设计修订以下既有口径：

- `2026-07-03-daily-fact-data-layer-design.md` 中整条日报内容统一解决冲突的设计。
- `2026-07-11-report-agent-design.md` 中自动生成模块二、模块三“下周工作计划”的设计。
- `2026-07-18-zhipu-weekly-ai-preview-design.md` 中依赖日报所属板块、敏捷小组或宽泛关键词扩大周报候选范围的设计。

冲突时以本设计为准。核心指标本身、海报渲染、月报和正式组织迁移沿用既有设计。

## 目标

- 防止后发群聊日报的空字段覆盖表单中已有的明日计划或风险信息。
- 保留日报事实的字段级来源、时间和处理说明，支持重复同步和异常恢复。
- 把人员身份、日报所属板块和周报供稿范围拆成边界明确的数据层。
- 允许一个成员为多个模块二板块提供事实，也允许其固定参与一个模块三板块。
- 允许成员只参与模块二，不参与模块三。
- 同一日报事项在模块二和模块三之间互斥，只进入一个目标板块。
- 使用负责人审核后的最终周报样例控制表达风格和信息粒度。
- 在不覆盖人工内容的前提下支持周五初次生成和周六安全刷新。
- 无事实依据不生成，空白内容不阻塞负责人填写或海报发布。

## 非目标

- 不自动生成模块二或模块三的“下周工作计划”。
- 不根据日报推断或填写核心指标。
- 不使用 AI 推断人员的组织身份、敏捷小组或人员类型。
- 不展示日报覆盖率、缺报人员名单或成员身份标签。
- 不把历史风格样例当成本周事实。
- 不要求所有成员都参与模块三。
- 不因日报缺失而编造内容、阻塞海报或催促迟到提交人。
- 本阶段不启用“历史账号说明”参与 OpenID 匹配。

## 数据边界

### 团队通讯录

团队通讯录维护稳定的人员身份和日报事实组织快照。保留现有字段：

| 字段 | 用途 |
| --- | --- |
| 团队名称 | 写入日报事实表“所属板块”，保存日报发生时的板块快照 |
| 团队成员 | 飞书人员字段，用于获得当前账号 OpenID |
| 成员真实姓名 | 日报提交人姓名的权威来源 |
| 团队身份 | 保留“组员/组长”，本阶段不参与日报合并或周报归集 |
| 直属上级 | 表示日报汇报人，用于事实快照和以后直属上级摘要 |
| 成员别名 | 匹配群聊日报中的简称、昵称 |
| 当前OpenID | 当前账号匹配和测试组织兼容 |
| 历史账号说明 | 仅作人工追溯，本阶段不参与自动匹配 |

通讯录不新增或维护以下字段：

- 人员类型。
- 敏捷小组。
- 分管领导。
- 模块二或模块三归属。

`团队名称`只表示日报事实的“所属板块”，不用于决定周报模块二或模块三归属。

### 日报统一事实表

日报统一事实表继续作为 AI 周报的唯一事实来源：

- `团队名称`写入事实表`所属板块`并保存当时快照。
- `成员真实姓名`写入`日报提交人姓名`。
- `直属上级`写入事实表同名字段。
- 不再读取、写入或修复`敏捷小组`。
- 表单与群聊的业务字段按“日报字段级合并规则”生成唯一有效事实。
- 周报只读取日报日期位于上周五至本周四闭区间且`事实记录状态=有效`的记录。
- 成员匹配优先使用 OpenID；缺失时允许用标准化后的真实姓名或成员别名精确匹配。

事实表增加一个隐藏技术字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 字段来源快照 | 多行文本 JSON | 保存今日总结、明日计划、风险三个字段各自的来源、来源时间和内容指纹 |

快照不保存额外正文，只保存追溯信息。例如：

```json
{
  "workItems": {
    "source": "chat",
    "sourceTime": 1784282400000,
    "fingerprint": "9e97d975f307e17c14f2a3f63a607881"
  },
  "tomorrowPlanItems": {
    "source": "form",
    "sourceTime": 1784278800000,
    "fingerprint": "0da501daa991a667507b9757f7407a15"
  },
  "riskItems": {
    "source": "form",
    "sourceTime": 1784278800000,
    "fingerprint": "d41d8cd98f00b204e9800998ecf8427e"
  }
}
```

### 周报来源映射表

新增“周报来源映射表”。日常维护视角下一名成员一行，且最多只有一条当前有效记录：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 成员 | 关联团队通讯录 | 必填，作为人员主键 |
| 成员真实姓名 | Lookup | 只读，用于检查 |
| 成员 OpenID | Lookup | 只读，优先用于事实匹配 |
| 模块二可归集板块 | 多选 | 允许多个，允许为空 |
| 模块三归属板块 | 单选 | 最多一个，允许为空 |
| 生效日期 | 日期 | 必填 |
| 失效日期 | 日期 | 可为空，闭区间有效 |
| 是否启用 | 复选框 | 仅启用记录参与归集 |
| 备注 | 多行文本 | 仅供配置说明，不发送给 AI |

该表描述“成员的日报可以为哪些周报板块提供事实”，不描述成员的组织身份。正式成员和外部协作人员使用完全相同的映射方式，不记录或展示人员类型。

归属变更时先关闭旧记录，再新增记录。出现以下情况时安全跳过并告警：

- 同一成员同一日报日期没有有效映射：该成员不参与 AI 周报。
- 同一成员同一日报日期存在多条有效映射：暂停该成员本期全部 AI 归集。
- 模块三归属为空：成员不参与模块三。

### 周报板块规则表

新增“周报板块规则表”，维护目标板块的业务边界和负责人：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 模块 | 单选 | 模块二或模块三 |
| 周报板块 | 文本或单选 | 必须与模板中的语义标题对应 |
| 内容类型 | 单选 | 本阶段只允许本周重点事项或本周工作进展 |
| 包含主题 | 多行文本 | 业务主题、系统名和稳定别名，一行一个 |
| 排除主题 | 多行文本 | 容易误归类的主题，一行一个 |
| 周报负责人 | 人员 | 允许一人或多人 |
| 是否启用 | 复选框 | 仅启用规则参与生成和提醒 |
| 备注 | 多行文本 | 仅供配置说明 |

例如：

- 模块二“线上营业厅项目组”：企业网银、企业手机银行等。
- 模块二“收单项目组”：收单业务及其阶段性成果。
- 模块三“对公客群经营及场景建设”：云缴费、云充值、网联前置、银联前置、银企直联、场景建设等。

周报负责人来自该表，不从团队身份、直属上级或日报内容中推断。

### 周报风格样例表

新增“周报风格样例表”。每条记录是一段负责人审核后的最终周报内容：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 模块 | 单选 | 模块二或模块三 |
| 周报板块 | 单选或文本 | 与板块规则表对应 |
| 内容类型 | 单选 | 本阶段只允许本周重点事项或本周工作进展 |
| 样例周次 | 文本 | 用于追溯 |
| 最终样例正文 | 多行文本 | 只能保存审核后的最终版本 |
| 审核人 | 人员 | 必填 |
| 审核时间 | 日期时间 | 必填 |
| 纳入优质样例 | 复选框 | 只有选中记录才可供 AI 使用 |
| 是否启用 | 复选框 | 支持停用错误样例 |
| 备注 | 多行文本 | 可选 |

系统不得自动把 AI 草稿或未经确认的海报内容加入样例库。每次生成优先读取同一模块、板块和内容类型最近三至五条启用优质样例；没有板块级样例时使用模块通用写作规则。

### 核心指标负责人表

新增“核心指标负责人表”，只维护模块一指标与提醒负责人的关系：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 指标名称 | 文本 | 必须与周报模板中的指标名称一致 |
| 指标负责人 | 人员 | 允许一人或多人 |
| 启用提醒 | 复选框 | 选中后才检查空白并发送提醒 |
| 是否启用 | 复选框 | 仅启用记录参与检查 |
| 备注 | 多行文本 | 仅供配置说明 |

该表不保存或生成指标值。系统只按指标名称动态定位目标 Cell，判断是否为空，并在周五 17:00 私聊负责人一次。

### 周报实例表扩展

周报实例表建议增加：

| 字段 | 用途 |
| --- | --- |
| AI 初次生成时间 | 记录周五生成时间 |
| AI 刷新时间 | 记录周六安全刷新时间 |
| AI 草稿快照 | 保存目标 Cell、AI 文本和内容哈希的 JSON |
| AI 证据快照 | 保存目标 Cell 对应 evidenceId 和事实记录 ID 的 JSON |

不增加日报覆盖率或缺报成员字段。

## 日报字段级合并规则

### 合并粒度

以下字段分别判断，不再共用一个整条记录胜者：

- 今日工作总结。
- 明日工作计划。
- 遇到的问题。

每个字段遵循：

1. 只有一个来源非空：使用非空内容。
2. 两个来源都非空且标准化内容一致：保留一份。
3. 两个来源都非空且内容不同：该字段按来源时间取最新。
4. 来源时间完全相同：表单优先，保证结果稳定。
5. 后发来源字段为空：视为“本次未提供”，不得清空已有非空内容。
6. 如确需删除已有事实，由管理员直接修改事实表；自动同步不把空值解释为删除指令。

同一来源重复提交时也使用上述字段规则。字段来源快照记录每个最终字段的来源和时间，使实时消息和定时重跑得到相同结果。

### 状态规则

`日报来源`和`有效来源`允许：

- `form`
- `chat`
- `form+chat`

最终三个业务字段来自多个来源时，`有效来源=form+chat`。`来源时间`保存所有最终字段来源时间的最大值；字段级时间以`字段来源快照`为准。

`日报来源`表示已经发现的来源集合；`有效来源`表示最终业务字段实际采用的来源集合。两来源内容完全一致时允许选择较新的字段来源用于追溯，但不得重复正文。

`合并状态`单选值调整为：

| 场景 | 合并状态 | 冲突状态 |
| --- | --- | --- |
| 只有一个来源 | 单来源 | 无冲突 |
| 两个来源提供的非空字段完全相同 | 重复已合并 | 无冲突 |
| 两个来源互相补充不同字段，没有重叠冲突 | 互补已合并 | 无冲突 |
| 至少一个重叠字段内容不同 | 按字段取最新 | 已自动处理 |

`自动处理说明`只记录字段和来源，不复制日报正文。例如：

```text
今日工作总结按来源时间采用群聊；明日工作计划保留表单；遇到的问题保留表单
```

合并后的完整业务字段重新计算`内容指纹`，`来源组合`继续保留表单记录 ID 和群聊消息 ID。

历史事实首次迁移时优先从表单日报表和群聊日报原始表重建字段来源快照。来源记录已不存在时，用事实表当前`有效来源`和`来源时间`初始化快照并保留现有正文，不猜测更细的历史来源。

### 示例

表单 17:00：

- 今日工作总结：完成 A。
- 明日工作计划：推进 B。

群聊 18:00：

- 今日工作总结：完成 C。
- 明日工作计划：空。

最终事实：

- 今日工作总结：完成 C，来源群聊。
- 明日工作计划：推进 B，来源表单。
- 日报来源和有效来源：`form+chat`。
- 合并状态：`按字段取最新`。
- 冲突状态：`已自动处理`。
- 事实记录状态：`有效`。

## 周报事项归集规则

### 候选人员

- 先按日报日期查找成员当时唯一有效的周报来源映射。
- `模块二可归集板块`为空时不参与模块二。
- `模块三归属板块`为空时不参与模块三。
- 日报`所属板块`只用于追溯，不自动改变周报来源映射。

### 事项级路由

每条日报的“今日工作总结”先拆成独立事项，再在该成员被允许的板块范围内路由：

1. 使用板块规则表的包含主题、排除主题和稳定别名构造允许目标。
2. 优先判断是否符合模块二具体项目的阶段性成果。
3. 符合模块二时进入唯一的模块二目标，不再进入模块三。
4. 不符合模块二但符合成员固定模块三板块业务范围时，进入模块三。
5. 无法唯一判断、同时命中多个目标或缺少业务依据时跳过并记录诊断，不让 AI 猜测。

因此模块二和模块三在“日报事项”层面互斥，但同一成员一周内的不同事项可以分别进入模块二和模块三。

例如同一成员本周同时从事收单和云缴费：

- 收单阶段性成果进入模块二“收单项目组”。
- 云缴费阶段性成果进入模块三“对公客群经营及场景建设”。
- 普通讨论、无结论会议和没有阶段变化的日常推进默认不进入周报。

## 本阶段生成范围

自动生成目标仅包括：

- 模块二：`本周重点事项说明`右侧一个目标 Cell。
- 模块三：`本周工作进展`右侧连续三个目标 Cell。

保持人工填写：

- 模块二`下周工作计划`。
- 模块三`下周工作计划`。
- 模块一全部核心指标。

程序不得读取明日工作计划后自动推断周报“下周工作计划”，也不得把本周已完成事项改写为未来计划。

## AI 压缩与校验

### 确定性预处理

发送给 AI 前由程序完成：

- 只读取上周五至本周四的有效事实。
- 按成员映射和板块规则完成事项级路由。
- 只提取本周工作事项，不携带明日或下周计划。
- 合并同一原始提交拆出的重复事实输入。
- 去除完全相同的重复事项并保留证据关系。
- 为每个事项生成稳定 evidenceId。
- 按具体周报板块分别调用模型，避免跨板块污染。

### 语义总结

AI 只负责：

- 合并同一主题一周内的连续进展。
- 将沟通、编写、测试、评审和修改等过程压缩为有依据的阶段性结果。
- 优先选择完成成果、明确交付物、阶段变化、重要业务进展、有结论的协调事项和已解决问题。
- 保留原始数字、日期、系统名、项目名和完成状态。
- 按当前板块最终样例的语气、结构和详略程度表达。

AI 默认忽略：

- 没有结论或成果的普通会议和参会记录。
- 重复出现但没有新增进展的事项。
- 纯过程性沟通和个人日常事务。
- 含义不明确、缺少上下文的碎片。
- 明日计划、下周计划和 AI 推测的后续动作。

周报正文默认不显示成员姓名。姓名只保留在后台证据链中。

模块二一个 Cell 可包含多条主题级进展，建议三至六条但不设硬上限。模块三最多使用三个 Cell，每个 Cell 一个主题级事项；不足三项时其余 Cell 保持空白。

### 写入前校验

每条 AI 输出必须引用至少一个当前板块、当前周期的 evidenceId，并依次通过：

1. JSON 结构校验。
2. 模板语义目标 Cell 白名单校验。
3. 当前板块 evidenceId 白名单校验。
4. 成员来源映射校验。
5. 模块二和模块三事项互斥校验。
6. 本周事项类型校验。
7. 模块三最多三个 Cell、每格一项校验。
8. 空内容和无证据内容丢弃。

硬性门槛为：错误人员归属为零、跨板块事项为零、同一事项跨模块重复为零、无本周证据陈述为零、数字和状态篡改为零、把本周事项写成下周计划为零。

## 自动化时序

### 周五 16:30：同步与首次生成

任务按以下顺序执行：

1. 确保本周实例工作表存在；复制后按当前周五命名为`数字金融部周报MMDD`并移动到最前。
2. 显式同步上周五至本周四的表单和群聊日报。
3. 按字段级规则重算事实。
4. 加载来源映射、板块规则和最终风格样例。
5. 按板块独立生成并校验本周内容。
6. 只向当前为空的目标 Cell 写入 AI 内容。
7. 保存 AI 草稿、哈希和证据快照。
8. 给 AI 写入 Cell 添加“AI总结生成，仅供参考”批注；批注不进入海报。

已有人工内容的 Cell 保持不变。

### 周五 17:00：负责人私聊

机器人按`周报板块规则表.周报负责人`取得 OpenID，以应用身份私聊。负责人不需要个人 OAuth，但必须：

- 位于应用可用范围内。
- 与应用属于同一组织。
- 应用已发布并具有发送消息权限。

同一负责人负责多个板块时合并成一条消息，内容包括：

- 负责板块。
- 已生成的 AI 草稿；没有依据时显示“本期暂无可用 AI 草稿，请直接进入周报表填写”。
- 本周周报 Wiki 链接。
- 审核、修改和完成填写的提醒。

消息不包含日报覆盖率、缺报成员、人员类型或敏捷小组。发送使用稳定幂等键；失败时聚合通知运维群，不自动改发业务群。

核心指标负责人未填写时也在周五 17:00 私聊提醒一次。到周六 10:30 仍未填写则保持空白，不再提醒，也不阻止海报生成。

### 周六 09:30：安全刷新

任务先同步截至执行时可获得的迟到日报，但不通知迟到提交人。

每个目标 Cell 独立判断：

- 当前内容与周五 AI 草稿一致：仍由 AI 持有，可使用新增事实刷新。
- 当前内容与周五 AI 草稿不同：视为人工修改，禁止覆盖。
- AI 内容被人工清空：视为人工修改，保持空白。
- 初次生成前已有人工内容：永久不参与自动刷新。
- 刷新为空、无证据或模型失败：保留周五内容，不主动清空。

模块三三个 Cell 分别保护。若刷新候选与已锁定人工 Cell 重复，则丢弃候选，不把重复内容移入其他 Cell。

### 周六 11:00：海报

- 海报直接读取工作表当前内容，不读取 AI 草稿快照。
- 空白板块、核心指标缺失或部分 AI 失败不阻止海报。
- 海报不展示 AI 批注、证据、技术告警或人员相关诊断。
- 海报发送到部门大群；发送时间继续通过配置修改。

三个分管团队的小群周报推送使用独立目标配置。测试阶段可统一发送到当前测试群，正式环境未获得群 ChatID 的团队保持停用，不影响部门海报。

## 异常处理

- 单个板块模型失败、超时或输出非法，只让该板块保持原值或空白。
- 来源映射缺失时跳过对应成员；同期映射冲突时暂停该成员 AI 归集。
- 板块规则不存在、目标不唯一或模板无对应板块时跳过并告警。
- 没有板块级风格样例时使用模块通用规则，不阻塞生成。
- 周六刷新失败时保留周五草稿。
- 私聊发送失败不改发业务群。
- 所有技术异常按一次任务聚合，通过`Reporting.adminChatIds`发送一次。
- 告警和日志不得包含完整日报正文、API Key、App Secret 或飞书资源令牌。

## 测试策略

### 日报字段级合并

- 表单有明日计划、后发群聊计划为空时保留表单计划。
- 群聊有明日计划、后发表单计划为空时保留群聊计划。
- 两来源同一字段相同为重复合并。
- 两来源提供不同字段为互补合并。
- 两来源同一字段冲突时仅该字段按时间取最新。
- 时间相同表单优先。
- 同一来源后发空值不清空已有事实。
- 字段来源快照、有效来源、来源时间和自动处理说明一致。
- 定时重跑和实时增量处理结果一致。
- 手工`事实记录状态=忽略`在重跑后保持不变。

### 来源映射与事项路由

- 一名成员可配置多个模块二允许板块和一个模块三板块。
- 模块二为空时只允许进入模块三。
- 模块三为空时只允许进入模块二。
- 缺少映射时两个模块均不进入。
- 同期存在两条映射时暂停该成员并告警。
- 同一成员不同事项可分别进入模块二和模块三。
- 同一事项最多进入一个目标，模块二匹配优先。
- 归属不受日报所属板块、群聊名称或人员身份标签影响。
- 历史周按日报日期选择当时生效的映射。

### AI 内容

- 只构建上周五至本周四本周事项输入。
- 不发送明日工作计划，不生成下周计划 Cell。
- 模块二允许多条，模块三最多三格且每格一项。
- 无结果会议默认不进入周报。
- 多日同主题进展压缩为一条。
- 正文默认不包含成员姓名。
- 每条输出可追溯到当前板块本周 evidenceId。
- 最终风格样例只影响表达，不得成为事实来源。

### 写入、提醒与海报

- 周五仅写空白 Cell。
- 周六只刷新仍等于 AI 草稿的 Cell。
- 人工修改、人工清空和初始人工内容均不覆盖。
- 模块三三个 Cell 独立保护。
- 一个板块失败不阻止其他板块写入。
- 同一负责人多个板块只收到一条私聊。
- 私聊不包含覆盖率、缺报人员或身份标签。
- 私聊失败只进入运维告警。
- 周六海报与工作表最终正文一致，且不包含 AI 批注。
- 完整测试套件无失败和取消项。

## 分阶段实施建议

### 阶段 1：事实层边界和字段级合并

1. 移除通讯录、日报事实和配置默认值中的敏捷小组映射。
2. 保持`团队名称 -> 所属板块`和`直属上级`事实快照。
3. 增加`字段来源快照`并实现三个业务字段独立合并。
4. 更新合并状态单选值为`单来源`、`重复已合并`、`互补已合并`、`按字段取最新`。
5. 用表单先发、群聊后发且群聊无计划的场景完成回归测试。
6. 对测试周期事实执行幂等重算，核对正文和字段来源。

### 阶段 2：周报映射和事项路由

1. 手工创建周报来源映射表和周报板块规则表。
2. 手工创建核心指标负责人表。
3. 导入成员允许目标、模块三固定目标、周报负责人和指标负责人。
4. 将预览分桶改为成员允许范围内的事项级路由。
5. 实现模块二优先、模块二和模块三事项互斥。
6. 在只读 JSON 预览中完成归属审计。

### 阶段 3：风格样例和 AI 质量

1. 手工创建周报风格样例表。
2. 每个板块导入三至五条负责人审核后的最终样例。
3. 调整提示词，只生成本周内容。
4. 完成证据、数字、状态、人员归属和跨模块重复评测。

### 阶段 4：工作表写入和负责人私聊

1. 扩展周报实例表的 AI 快照和通知状态字段。
2. 接入周五 16:30 实例确保、事实同步、AI 生成和空 Cell 写入。
3. 接入周五 17:00 负责人合并私聊和核心指标一次提醒。
4. 验证应用权限、可用范围、OpenID 和私聊失败告警。

### 阶段 5：刷新、海报和正式化

1. 接入周六 09:30 迟到事实同步和人工修改保护。
2. 验证周六 10:30 核心指标空白不阻塞。
3. 验证周六 11:00 海报读取最终工作表并发送部门大群。
4. 测试三个小团队统一推送测试群的配置，再按取得的 ChatID 分别启用。
5. 完成服务器定时任务、运维告警、幂等重跑和异常恢复验收。

本设计通过前不得开启自动写入正式组织周报表。
