# 周报来源映射与本周进展 AI 生成设计

## 文档定位

本设计修订以下既有口径：

- `2026-07-11-report-agent-design.md` 中模块二、模块三自动生成“下周工作计划”的设计。
- `2026-07-18-zhipu-weekly-ai-preview-design.md` 中依赖日报“所属板块”、板块别名或事项关键词扩大模块三候选人员范围的设计。

冲突时以本设计为准。本设计只处理周报来源映射、模块二和模块三的本周内容生成、风格样例、人工修改保护及两次生成时序。核心指标、海报渲染、月报和正式组织迁移沿用既有设计。

## 目标

- 把“成员是谁”和“成员为哪个周报板块提供事实”拆成两个明确的数据边界。
- 模块二严格按成员当时的敏捷小组归集。
- 模块三严格按一人一个固定部门管理板块归集，并允许成员不参与模块三。
- 只生成模块二“本周重点事项说明”和模块三“本周工作进展”。
- 用负责人审核后的最终周报样例控制表达风格和信息粒度。
- 在不覆盖人工内容的前提下，支持周五初次生成和周六迟到日报安全刷新。
- 无事实依据不生成，低覆盖率不阻塞人工协作和海报发布。

## 非目标

- 不自动生成模块二或模块三的“下周工作计划”。
- 不根据日报推断或填写核心指标。
- 不使用 AI 判断成员属于哪个模块三板块。
- 不把历史风格样例当成本周事实。
- 不要求所有成员都参与模块三。
- 不因日报缺失而编造内容、阻塞海报或催促迟到提交人。

## 数据边界

### 团队通讯录

团队通讯录继续维护稳定的人员身份和事实层组织快照来源：

- 团队成员、成员真实姓名和 OpenID。
- 成员别名、历史账号和成员状态。
- 直属上级。
- 敏捷小组。

团队通讯录不新增模块三部门管理归属，也不承担周报板块配置职责。

### 周报来源映射表

新增“周报来源映射表”。日常维护视角下一名成员一行，且最多只有一条当前有效记录。归属变更时先关闭旧记录，再新增一条记录，以便历史周报仍可按当时归属重跑。建议字段如下：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 成员 | 关联团队通讯录 | 必填，作为人员主键 |
| 成员真实姓名 | Lookup | 只读，用于检查 |
| 成员 OpenID | Lookup | 只读，优先用于事实匹配 |
| 参与模块二 | 复选框 | 未选中时不进入模块二 AI 候选 |
| 模块二敏捷小组 | Lookup | 只读，展示通讯录当前敏捷小组 |
| 模块三归属板块 | 单选 | 最多一个，允许为空 |
| 生效日期 | 日期 | 必填 |
| 失效日期 | 日期 | 可为空，闭区间有效 |
| 是否启用 | 复选框 | 仅启用记录参与归集 |
| 备注 | 多行文本 | 仅供配置说明，不发送给 AI |

同一成员在同一日报日期最多只能匹配一条启用且有效的映射。出现零条时，该成员不参与 AI 周报；出现多条时视为配置冲突，该成员本周所有 AI 归集暂停并进入运维告警。历史失效记录不出现在默认维护视图中。

模块三归属为空表示成员只为敏捷小组负责，不参与部门管理工作周报来源。

### 日报统一事实表

日报统一事实表继续作为本周事实的唯一来源：

- 只读取日报日期位于周一至周五闭区间且“事实记录状态”为“有效”的记录。
- 表单和群聊冲突沿用事实层已经确定的有效结果。
- 模块二使用事实记录中固化的敏捷小组快照，不用当前通讯录覆盖历史归属。
- “所属板块”、群聊名称和关键词只可作为追溯信息，不得决定模块三人员归属。
- 成员匹配优先使用 OpenID；缺失时仅允许用标准化后的成员真实姓名精确匹配。

### 周报风格样例表

新增“周报风格样例表”。每条记录是一段负责人审核后的最终周报内容：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 模块 | 单选 | 模块二或模块三 |
| 周报板块 | 单选或文本 | 具体敏捷小组或部门管理板块 |
| 内容类型 | 单选 | 本阶段只允许本周重点事项或本周工作进展 |
| 样例周次 | 文本 | 用于追溯 |
| 最终样例正文 | 多行文本 | 只能保存审核后的最终版本 |
| 审核人 | 人员 | 必填 |
| 审核时间 | 日期时间 | 必填 |
| 纳入优质样例 | 复选框 | 只有选中记录才可供 AI 使用 |
| 是否启用 | 复选框 | 支持停用错误样例 |
| 备注 | 多行文本 | 可选 |

系统不得自动把 AI 草稿或已发布海报内容加入样例库。每次生成优先读取同一模块、同一板块和同一内容类型最近的三至五条启用优质样例；没有板块级样例时使用模块通用写作规则。

### 周报实例表扩展

周报实例表建议增加以下字段：

| 字段 | 用途 |
| --- | --- |
| AI 初次生成时间 | 记录周五生成时间 |
| AI 刷新时间 | 记录周六安全刷新时间 |
| AI 草稿快照 | 保存目标 Cell、AI 文本和内容哈希的 JSON |
| AI 证据快照 | 保存目标 Cell 对应 evidenceId 和事实记录 ID 的 JSON |
| AI 生成状态 | 未生成、部分成功、成功或失败 |
| 日报覆盖率摘要 | 保存各板块应参与人数、已提交人数和覆盖率 |

快照用于人工修改保护和异常恢复，不作为普通周报正文展示。

## 归集规则

### 模块二

- 先要求成员存在唯一有效的周报来源映射，且“参与模块二”为真。
- 再按日报事实中的敏捷小组精确进入对应模块二板块。
- 板块别名只用于兼容同一敏捷小组的已知名称写法，不得把其他敏捷小组成员拉入。
- 同一成员可以同时参与其敏捷小组的模块二和其固定归属板块的模块三。

### 模块三

- 只按周报来源映射表中的“模块三归属板块”确定候选人员。
- 每名成员最多进入一个模块三板块。
- 模块三归属为空的成员不得进入任何模块三候选集。
- 日报“所属板块”、项目字段、群聊名称、敏捷小组和事项关键词均不得改变人员归属。
- 关键词和 AI 只能在已经归属该板块的成员事项中筛选重点，不能跨板块拉人。

## 本阶段生成范围

自动生成目标仅包括：

- 模块二：`本周重点事项说明`右侧的一个目标 Cell。
- 模块三：`本周工作进展`右侧连续三个目标 Cell。

以下目标保持人工填写：

- 模块二：`下周工作计划`。
- 模块三：`下周工作计划`。
- 模块一全部核心指标。

程序不得读取本周事项后推断下周计划，也不得使用“待、跟进、推进、上线”等词语把本周事项转写为计划。

## AI 压缩规则

### 确定性预处理

发送给 AI 前由程序完成：

- 按来源映射过滤候选成员。
- 只提取本周工作事项，不携带下周计划。
- 合并同一原始提交拆出的重复事实输入。
- 去除完全相同的重复事项，同时保留不同来源的证据关系。
- 为每个事项生成稳定的 evidenceId。
- 按具体周报板块分别调用模型，避免跨板块上下文污染。

### 语义总结

AI 只负责：

- 合并一周内同一主题的连续进展。
- 将沟通、编写、测试、评审和修改等过程压缩为有依据的阶段性结果。
- 优先选择完成成果、明确交付物、阶段变化、重要业务进展、有结论的协调事项和已解决问题。
- 保留原始数字、日期、系统名、项目名和完成状态。
- 按当前板块最终样例的语气、结构和详略程度表达。

AI 默认忽略：

- 没有结论或成果的普通会议和参会记录。
- 重复出现但没有新增进展的事项。
- 纯过程性沟通和个人日常事务。
- 含义不明确、缺少上下文的碎片。
- 下周计划和 AI 推测的后续动作。

周报正文默认不显示成员姓名。姓名只保留在后台证据链中；只有最终风格样例明确要求责任人，或事项本身必须说明责任人时，正文才可出现姓名。

### 输出粒度

模块二一个 Cell 可包含多条主题级进展，建议三至六条但不设硬上限。独立且重要的事项超过六条时允许保留，同一主题的逐日细节必须合并。

模块三最多使用三个 Cell，每个 Cell 一个主题级事项，按业务重要程度选择而不是按人员平均分配。不足三项时其余 Cell 保持空白，不得用低价值内容补齐。

## 事实与输出校验

每条 AI 输出必须引用至少一个本周候选集内的 evidenceId。历史样例中的文字、旧项目和旧数字不得成为 evidenceId。

写入前必须通过：

1. JSON 结构校验。
2. 模板语义目标 Cell 白名单校验。
3. 当前板块 evidenceId 白名单校验。
4. 模块二和模块三人员来源校验。
5. 本周事项类型校验。
6. 模块三最多三个 Cell、每格一项校验。
7. 空内容和无证据内容丢弃。

硬性质量门槛为：错误人员归属为零、模块三跨板块为零、无本周证据陈述为零、数字和状态篡改为零、把本周事项写成下周计划为零、为填满 Cell 生成低价值内容为零。

## 写入与人工修改保护

### 周五 18:00 初次生成

任务按以下顺序执行：

1. 显式同步本周最新日报事实，不依赖日常 18:10 同步任务是否已经运行。
2. 加载周报实例、来源映射和风格样例。
3. 按板块独立生成并校验本周内容。
4. 只向当前为空的目标 Cell 写入 AI 内容。
5. 已有人工内容的 Cell 保持不变。
6. 保存 AI 草稿、哈希、证据和覆盖率快照。
7. 给 AI 写入 Cell 添加“AI总结生成，仅供参考”批注；批注不进入海报正文。

### 周六 09:30 安全刷新

任务先同步迟到日报，但不向迟到提交人或业务群发送通知。

每个目标 Cell 独立判断：

- 当前内容与周五 AI 草稿一致时，视为仍由 AI 持有，可使用新增事实刷新。
- 当前内容与周五 AI 草稿不同，视为人工修改，禁止覆盖。
- AI 写入后被人工清空同样视为人工修改，必须保持空白。
- 初次生成前已有人工内容的 Cell 永久不参与自动刷新。
- 刷新结果为空、无有效证据或模型失败时保留周五内容，不主动清空。

模块三三个 Cell 分别保护。刷新候选若与已锁定人工 Cell 内容重复，则丢弃该候选，不把重复内容移入其他 Cell。

### 周六 11:00 海报

海报直接读取工作表当前内容。空白板块、低日报覆盖率或部分 AI 失败均不阻止海报生成。海报不得展示 AI 批注、覆盖率、证据和技术告警。

## 覆盖率与缺失事实

每个板块记录：

- 应参与成员数。
- 本周至少有一条有效日报的成员数。
- 未提供有效日报的成员数。
- 日报覆盖率。
- 生成成功、空白或异常状态。

覆盖率低不阻止生成。AI 只基于已提交成员的事实，不使用历史周报补全本周缺失内容。一个板块没有任何有效事项时保持空白，由周报负责人手动填写。

## 异常处理

- 一个板块模型失败、超时或输出非法，只让该板块保持原值或空白，不影响其他板块。
- 来源映射缺失时跳过对应成员；来源映射冲突时暂停该成员全部 AI 归集。
- 模块三配置了模板中不存在的板块时跳过并告警。
- 没有板块级风格样例时使用模块通用规则，不阻塞生成。
- 周六刷新失败时保留周五草稿。
- 所有技术异常按一次任务聚合，通过现有运维告警配置发送一次，不在普通业务群发送原始错误。
- 告警和日志不得包含完整日报正文、API Key、App Secret 或飞书资源令牌。

## 测试策略

### 来源映射

- 一名成员一条有效映射时可正常归集。
- 模块三为空时只进入模块二。
- 不参与模块二时不得进入模块二。
- 缺少映射时两个模块均不进入。
- 同期存在两条映射时暂停该成员并产生安全告警。
- 模块三不受日报所属板块、关键词和群聊名称影响。
- 历史周按日报日期选择当时生效的映射。

### AI 内容

- 只构建本周事项输入，不发送下周计划。
- 不生成任何下周计划 Cell。
- 模块二允许多条，模块三最多三格且每格一项。
- 无结果会议默认不进入周报。
- 多日同主题进展压缩为一条。
- 正文默认不包含成员姓名。
- 每条输出可追溯到当前板块本周 evidenceId。
- 风格样例只影响表达，不得成为事实来源。

### 写入保护

- 周五仅写空白 Cell。
- 周六只刷新仍等于 AI 草稿的 Cell。
- 人工修改、人工清空和初始人工内容均不覆盖。
- 模块三三个 Cell 独立保护。
- 一个板块失败不阻止其他板块写入。
- 刷新失败不清空周五内容。

### 集成验收

- 在测试组织完成一周事实的只读预览，错误人员归属和跨板块均为零。
- 启用写入后验证模块二只写本周重点事项、模块三只写本周工作进展。
- 手工修改一个 AI Cell 后运行周六刷新，确认该 Cell 不变而其他 AI Cell 可刷新。
- 迟到日报可进入周六未锁定 AI Cell，且不发送迟到通知。
- 周六 11:00 海报内容与工作表最终正文一致，且不包含 AI 批注。
- 完整测试套件无失败和取消项。

## 分阶段实施建议

1. 创建并初始化周报来源映射表，先完成成员归属审计。
2. 将预览分桶改为严格来源映射，并停止构建下周计划候选。
3. 创建周报风格样例表，导入每个板块三至五条最终样例。
4. 调整提示词和质量评测，先在只读 JSON 预览中验收。
5. 扩展周报实例表，接入 Cell 快照、证据快照和人工修改保护。
6. 启用周五 18:00 初次生成和周六 09:30 安全刷新。
7. 验证周六 11:00 海报读取最终工作表内容。

本设计通过前不得开启自动写入生产周报表。
