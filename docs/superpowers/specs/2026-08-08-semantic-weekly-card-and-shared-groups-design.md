# 部门周报语义分类、负责人卡片与共享多群聊设计

## 背景

当前系统已经能够从飞书群聊和多维表格表单采集日报，按成员和日期归集到日报统一事实表，并具备周报实例、AI 只读预览、负责人提醒和确定性海报的基础能力。

现有周报路由把板块关键词作为准入条件。真实日报使用简称、业务术语和自然语言表达时，大量有效事项会在调用 AI 前被标记为 `no_topic_match`。同时，现有配置把表资源放在单个 group 内，不能正确表达“多个日报群共享同一套表、同一份部门周报”的关系。

本设计解决三个问题：

1. 使用两阶段 AI 完成语义分类和周报总结。
2. 通过负责人私聊交互卡片审核并写入周报 Cell。
3. 将多个日报群与唯一共享数据域分离，避免重复同步和重复周报任务。

## 范围

本轮包括：

- 部门周报模块二、模块三的 AI 语义分类与总结。
- 核心指标的负责人卡片填写和确定性完成度计算。
- 一名负责人一张汇总卡片，以及卡片提交、冲突和覆盖流程。
- 多个日报群共享日报表、事实表、通讯录和周报资源的配置结构。
- 周五、周日四阶段部门周报调度。

本轮不包括：

- 小团队分类、小团队海报和小群推送。
- 月报配置、协作和文档生成。
- 自动学习或在线分类纠错系统。
- 机器人在负责人确认前自动填写任何业务 Cell。

## 核心原则

- 日报统一事实表是 AI 周报的唯一事实来源。
- 来源映射是分类目标的唯一硬边界。
- 包含主题、排除主题、正例和反例只作为 AI 语义提示。
- 一条日报工作事项是最小分类单元，不由 AI 再拆分。
- 每条事项只能归入一个允许目标，模块二和模块三互斥。
- AI 草稿只通过私聊卡片交付；负责人明确提交后机器人才能写 Sheet。
- 无依据不生成，不使用关键词模板或其他板块内容兜底。
- 最终部门海报只读取周报 Sheet，不读取卡片草稿。

## 总体架构

```text
有效日报事实
  -> 候选目标构建
  -> AI 语义分类
  -> 确定性分类校验
  -> 按周报目标分组
  -> AI 板块总结
  -> 逐条事实校验
  -> 负责人汇总卡片
  -> 负责人提交
  -> Cell 冲突检查与写入
  -> 最终 Sheet
  -> 部门海报
```

分类和总结使用两个独立边界。分类错误可以定位到单条 evidenceId；总结错误可以定位到具体目标和引用证据。任一目标失败不得影响其他目标。

## 共享多群聊配置

### 配置结构

采用一套共享资源和多个轻量群聊：

```json
{
  "sharedResources": {
    "key": "digital-finance",
    "name": "数字金融部",
    "dailyTable": {},
    "chatDailyRawTable": {},
    "dailyFactTable": {},
    "contactTable": {},
    "weeklySourceMappingTable": {},
    "weeklySectionRuleTable": {},
    "weeklyStyleExampleTable": {},
    "coreMetricOwnerTable": {},
    "weeklyInstanceTable": {},
    "weeklySheet": {},
    "weeklyDelivery": {}
  },
  "groups": [
    {
      "enabled": true,
      "chatId": "oc_group_a",
      "name": "对公项目组日报群",
      "project": "公司项目组",
      "pushChatId": "oc_group_a_push"
    }
  ]
}
```

顶层时区、调度和运维通知配置保持不变。新结构下 group 内不得重复声明共享表或周报资源。

### 运行时边界

标准化配置输出：

- `chatGroups`：消息入口、历史消息补采和来源追溯。
- `reportingUnits`：共享日报同步、负责人推送、周报工作流和部门海报。本轮只有一个 reporting unit。

实时消息按 chatId 找到 chat group，再临时组合群聊元数据和共享资源。表单同步、事实重算、周报分类和周报调度只遍历 reporting unit 一次。

群配置中的 `project` 仅保存日报来源语境，不决定事实表中的所属板块。日报提交人、所属板块和直属上级仍以团队通讯录匹配结果为准。

`pushChatId` 本轮不使用，保留给后续小团队推送。多个 group 可以在测试阶段配置相同 pushChatId。

### 配置校验和迁移

- `sharedResources.key`、`sharedResources.name`必填。
- 启用 group 的 chatId、name、project 必填。
- chatId 必须唯一；pushChatId 不要求唯一。
- 表结构校验只检查共享资源一次。
- 旧单 group 结构兼容一个过渡版本，但新配置和文档只使用共享结构。
- 默认、个人、正式示例和正式配置统一迁移。

## 第一阶段：AI 语义分类

### 候选输入

程序根据周报来源映射，为每条有效工作事项构建允许目标。输入不包含人员身份，只包含：

- evidenceId、日报日期和工作事项原文。
- 允许目标的稳定 targetId、模块、板块和内容类型。
- 各目标的业务范围说明。
- 包含主题、排除主题、分类正例和分类反例。

targetId 使用周报板块规则表的规则唯一键，不使用 Cell 坐标。

没有有效来源映射的事项不调用模型，记录 `unmapped_member`。来源映射冲突继续安全跳过。

### 分类输出

每条输入必须返回：

```json
{
  "evidenceId": "rec_xxx:current:workItems:2",
  "targetId": "模块三-对公客群经营及场景建设-本周工作进展",
  "confidence": "high",
  "reason": "事项明确涉及银企直联证书管理"
}
```

置信度规则：

- `high`：明确出现业务、系统、项目或可识别对象。
- `medium`：没有直接主题词，但完整语义可以合理确定板块。
- `low`：只能判断最可能板块，文本宽泛或信息不足。

AI 必须在 allowedTargets 中选择一个目标。高、中置信度进入板块总结；低置信度不进入草稿正文，作为“待负责人判断事项”发送给 AI 选择的目标负责人。

### 分类校验

- evidenceId 必须来自当前批次。
- targetId 必须属于该事项的 allowedTargets。
- 每条事项只能有一个结果。
- 模型不得拆分、改写或合并分类输入。
- 缺失结果、重复结果、非法 JSON 和越权目标均记为分类失败。
- 分类失败不使用旧关键词路由兜底。

分类按受控 token 数量分批执行。同一批中每条事项携带自己的允许目标，防止不同成员之间串板块。

## 第二阶段：AI 板块总结

每个目标独立接收：

- 当前周期高、中置信度事项及 evidenceId。
- 目标业务范围和内容类型。
- 最近三至五条同目标、已审核且启用的最终周报样例。

AI 必须合并多日重复事项，提炼阶段性成果、当前进展和已确认事项。沟通、协调和讨论不能被关键词直接删除；只有缺少可确认进展时才保持准确的推进表述或不生成。

AI 不得生成下周计划，不得添加事实中不存在的项目、数字、日期、状态、责任人或姓名。历史样例只影响表达风格，不构成本周事实。

模块二对应一个多行 Cell，不设置硬性条数上限。模块三输出一至三条，每条对应一个 Cell。

输出按条校验：

- evidenceId 必须属于当前目标。
- 数字、日期、状态和责任表达必须有被引用事实支持。
- 不允许姓名、下周计划或未知目标。
- 模块三不得超过三条。
- 单条非法只删除该条，不清空同目标其他合法内容。

## 负责人交互卡片

### 卡片聚合

同一负责人每期只收到一张私聊汇总卡片。卡片按目标分区，包含：

- 模块、板块、内容类型和当前处理状态。
- 可编辑 AI 草稿。
- 低置信度待判断事项。
- 周报 Wiki 链接。
- 采用并写入、修改后提交和打开周报操作。

模块二使用一个多行输入区域。模块三显示最多三个独立可编辑事项，允许一至三条，一次提交整个板块。空余输入不会主动清空已有 Cell。

### 写入授权

卡片创建时不写业务 Cell。收到 card action 回调后，服务端重新读取负责人配置并校验操作人 OpenID。后端只接受 instanceKey 和 targetId，并通过本期模板语义映射定位 Cell；不得接受卡片提交任意 Cell 地址。

只有当前启用负责人可以提交。转发卡片不能授权其他人写入。

### 冲突与覆盖

提交前实时读取目标 Cell：

- Cell 为空：直接写入。
- Cell 非空：卡片展示当前内容和准备写入内容，负责人选择保留、确认覆盖或打开周报。
- 确认覆盖前再次比较当前内容摘要；内容已变化则取消旧确认并刷新冲突信息。

相同实例和 targetId 的操作串行执行，并使用幂等操作键。模块三逐 Cell 检查冲突；部分失败时只重试失败项。

## 核心指标卡片

核心指标不使用 AI。核心指标负责人表新增：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 年度指标值 | 数字 | 必须大于0 |
| 单位 | 单选 | 例如亿、万 |
| 完成度小数位 | 单选 | 0、1、2 |

负责人只输入本周完成数字。程序计算：

```text
完成度 = 本周完成值 / 年度指标值 * 100%
```

完成度不设置上限，允许显示 `323.2%`。按配置的小数位标准四舍五入，并保留配置要求的尾随零。

程序按指标名称动态定位目标 Cell，生成完整文本：

```text
年度指标138亿，本周完成86.44亿，完成度63%
```

年度指标、单位和小数位只能来自配置表。非数字输入和年度指标为0时拒绝提交。核心指标 Cell 使用与模块二、模块三相同的冲突、覆盖、权限和幂等规则。

周报板块规则表新增：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 业务范围说明 | 多行文本 | 描述板块负责的业务边界 |
| 分类正例 | 多行文本 | 一行一个典型归类案例 |
| 分类反例 | 多行文本 | 一行一个容易误归类的案例 |

本轮不新增数据表。周报实例表继续使用 AI 草稿快照、AI 证据快照、负责人通知明细、负责人通知状态和最后错误摘要。快照保存标识、分类、置信度、理由、哈希和状态，避免重复保存完整日报正文。

## 调度

日报事实读取窗口为上周五至本周五闭区间；Sheet 展示周期为本周一至本周五。

### 周五 09:00：生成草稿

1. 同步当前可获取的有效日报。
2. 创建或复用本周周报 Sheet，并填写展示周期。
3. 加载来源映射、板块规则和历史样例。
4. 执行分类、校验、板块总结和逐条事实校验。
5. 保存分类、草稿和证据快照。
6. 不写业务 Cell，不发送负责人卡片。

### 周五 16:00：发送卡片

按负责人聚合模块二、模块三、低置信度事项和核心指标输入，并发送一张汇总卡片。各目标独立提交，不要求一次完成整张卡片。

### 周日 09:00：刷新和提醒

重新同步日报并刷新尚未完成目标的草稿。Cell 已有内容视为已完成；负责人已通过卡片提交的内容不自动更新。仅更新和提醒未完成部分。

### 周日 12:00：部门海报

读取最终 Sheet，使用 Node.js 确定性生成部门海报并发送部门大群。空白内容不阻止海报。

海报发送后卡片继续可用。后续提交只更新 Sheet，不自动撤回或重发海报；卡片必须提示这一点，并在周报实例明细中记录 `changedAfterPublish`。新版海报只能由管理员手动触发。

所有新调度默认关闭，完成正式组织受控验收后逐个启用。

## 异常处理

- 单条分类失败只影响该事项。
- 单个目标总结失败只影响该目标。
- 模型超时有限重试，仍失败则显示无可用草稿。
- 不使用模板内容、关键词硬路由或其他板块内容兜底。
- 写入前失败保持 Cell 原样，并允许负责人重试。
- Sheet 写入成功但卡片更新失败时，以 Sheet 为准并通过重新读取恢复状态。
- Sheet 写入成功后才记录“已写入”。
- 技术异常按任务聚合并脱敏通知运维，不包含完整日报正文、密钥或飞书资源标识。

## 测试与验收

### 本地自动化测试

- 新旧配置结构标准化和一次性共享任务遍历。
- 多 chat group 实时路由、来源追溯、历史补采和唯一 chatId 校验。
- 同一共享资源不会被表单同步、事实重算或周报任务重复处理。
- 分类 JSON、允许目标、单目标互斥、置信度和低置信度分流。
- 无 `no_topic_match` 关键词硬门槛。
- 板块总结去重、事实校验、模块二多行和模块三一至三条。
- 一名负责人一张卡片、实时权限校验和转发卡片拒绝。
- 空 Cell 写入、非空冲突、二次覆盖、并发变化和重复点击幂等。
- 模块三整体提交和逐 Cell 部分失败恢复。
- 核心指标格式、0/1/2位小数、超过100%、非法输入和冲突覆盖。
- 周五09:00不写不发、16:00发卡片、周日09:00只提醒未完成、12:00读取 Sheet 发布。
- 海报发布后修改只更新 Sheet 并记录状态。

### AI 质量验证

使用约50条人工标注真实日报事项，覆盖明确主题、简称、无直接关键词、普通工单、沟通事项和模块二/三易混淆场景。

硬性要求：

- 越权目标为0。
- 一事多目标为0。
- 无依据数字、状态和责任人为0。
- 低置信度事项全部可见。
- 映射完整的事项不再因缺少关键词直接丢弃。

目标分类准确率达到90%以上。未达到时优先完善业务范围、正反例和 Prompt，不建设自动学习系统。

### 正式组织受控验收

所有调度保持关闭，依次执行：

1. 校验共享表结构和群聊配置。
2. 运行只读分类与总结预览。
3. 人工核对标注集。
4. 只向测试负责人发送卡片。
5. 在复制的测试周报 Sheet 验证提交、冲突和覆盖。
6. 验证核心指标填写和计算。
7. 生成部门海报并只发送测试群。
8. 重跑相同任务验证幂等性。
9. 验收后逐个启用正式调度。

## 成功标准

- 多个日报群共享一套表时不会重复同步、重复生成周报或重复发送卡片。
- AI 分类不再依赖关键词硬匹配，且不能越过来源映射。
- 负责人无需复制 AI 草稿，可在私聊卡片中审核后安全写入目标 Cell。
- 模块三支持一至三条整体提交，核心指标由程序确定性计算。
- 机器人在负责人提交前不修改业务 Cell。
- 部门海报始终基于发送时的最终 Sheet 内容。
