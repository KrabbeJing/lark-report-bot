# 日报与周报智能体表格字段字典

## 使用范围

本清单覆盖当前“日报事实层 + AI 周报 + 负责人提醒 + 海报发布”阶段。

当前共需要：

- 9 张飞书多维表格数据表。
- 1 个飞书电子表格年度周报工作簿，其中包含一个模板 Sheet 和每周复制的实例 Sheet。

其中：

- 已存在：表单日报表、群聊日报原始表、日报统一事实表、团队通讯录、周报实例表。
- 本轮新增：周报来源映射表、周报板块规则表、周报风格样例表、核心指标负责人表。
- 本轮扩展：日报统一事实表、周报实例表。

月报配置表和月报实例表不在本轮创建范围内，待周报流程验收后单独设计。

## 共享资源拓扑与执行粒度

配置文件将共享表和聊天入口分开管理。一个 `sharedResources` 对象对应一个 reporting unit，拥有本部门的日报表、群聊日报原始表、统一事实表、通讯录、周报配置表、周报实例表、周报 Sheet 和投递配置；`groups` 只保留 `enabled`、`chatId`、`name`、`project`、`pushChatId`。

新增日报群不需要复制任何表配置，只需增加轻量 group：

```json
{
  "enabled": true,
  "chatId": "oc_new_daily_chat",
  "name": "新日报群",
  "project": "来源板块名称",
  "pushChatId": "oc_test_or_future_target"
}
```

群聊回放按 chat 分别读取并保留各自来源元数据；事实同步、直属上级摘要、周报预览、周报实例、周报阶段工作流和本 catalog 的 schema 校验按 reporting unit 各执行一次。`project` 仅是来源元数据，不是事实组织归属，事实表的所属板块和直属上级以通讯录匹配快照为准。`chatId` 必须唯一，`pushChatId` 可在测试时共享。

迁移检查应确认：`sharedResources` 存在且资源配置只出现一次；原始 group 不包含共享资源字段；自动调度保持关闭；formal example 中 ChatID、Base token、Sheet token 等继续使用占位值或空值。已有单 group 配置保留一版兼容读取能力，完成迁移后再执行只读 schema 校验。

## 通用约定

- 日期字段统一使用飞书“日期”。
- 执行时间统一使用飞书“日期时间”。
- OpenID、Token、SheetID、业务唯一键统一使用“单行文本”。
- JSON 快照统一使用“多行文本”，并放入仅管理员可见的技术视图。
- 人员字段允许多选时在飞书字段设置中开启“可选择多个人”。
- 单选、多选的选项必须预先创建；代码不得依赖自动创建未知选项。
- API Key、App Secret、模型密钥和服务器私钥不得写入任何表格。

## 表 1：表单日报表

**状态：** 已存在。

**用途：** 接收飞书表单日报。系统读取系统自动字段`创建时间`和`最后更新时间`作为来源时间，不需要手工创建这两个字段。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 日报日期 | 日期 | 是 | 日报实际归属日期 |
| 日报提交人 | 创建人（正式组织）；测试组织可为人员 | 是 | 使用提交记录的创建人作为日报提交人 |
| 所属板块 | 查找引用 | 否 | 引用`团队通讯录.团队名称`，条件为`团队成员 = 日报提交人`；最终事实以团队通讯录`团队名称`为准 |
| 今日工作总结 | 多行文本 | 是 | 可填写多条 |
| 明日工作计划 | 多行文本 | 否 | 空值不得清空另一来源已有计划 |
| 遇到的问题 | 多行文本 | 否 | 空值不得清空另一来源已有问题 |
| 直属上级 | 查找引用 | 否 | 引用`团队通讯录.直属上级`，条件为`团队成员 = 日报提交人`；最终事实以团队通讯录为准 |
| AI汇总 | 多行文本 | 否 | 兼容旧表，本轮不读取、不写入 |

表中其他现有字段可以保留，但不得作为周报人员归属依据。

## 表 5：周报来源映射表

**状态：** 本轮新增。

**用途：** 定义每名成员允许为哪些模块二板块供稿，以及其唯一的模块三归属。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 映射唯一键 | 单行文本，主字段 | 是 | 建议`成员真实姓名-生效日期` |
| 成员 | 人员 | 是 | 每条只填写一名成员；按人员 OpenID 与团队通讯录匹配 |
| 成员真实姓名 | Lookup | 是，只读 | Lookup 团队通讯录同名字段 |
| 成员OpenID | Lookup | 否，只读 | Lookup 团队通讯录`当前OpenID` |
| 模块二可归集板块 | 多选 | 否 | 允许多个；空表示不参与模块二 |
| 模块三归属板块 | 单选 | 否 | 最多一个；空表示不参与模块三 |
| 生效日期 | 日期 | 是 | 闭区间起始 |
| 失效日期 | 日期 | 否 | 闭区间结束；空表示持续有效 |
| 是否启用 | 复选框 | 是 | 只有选中记录参与 |
| 备注 | 多行文本 | 否 | 不发送给 AI |

程序以`成员`关联记录连接团队通讯录并读取真实姓名、人员字段和当前 OpenID。两个 Lookup 字段主要用于表格维护人员检查，不作为唯一运行数据源。

`模块二可归集板块`初始选项：

- `融羲项目组`
- `收单项目组`
- `线上营业厅项目组`
- `手机银行项目组`
- `新核心项目组`

`模块三归属板块`初始选项：

- `零售大众客群经营`
- `对公客群经营及场景建设`
- `渠道创新建设`
- `业务风控合规`
- `业务转型推动`

这些选项必须与当前周报模板中的板块标题一致。模板后续新增板块时，先更新本表和板块规则表选项，再启用代码。

### 小群模块化海报配置

小群海报不读取部门周报 Sheet 的最终内容，而是重新读取本期有效日报，经过周报来源映射和板块规则路由后，按`weeklyDelivery.smallTeams`配置筛选和分类。每个启用的小团队配置以下字段：

| 配置字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | 字符串 | 小团队稳定标识，用于图片文件名和幂等键 |
| `chatId` | 字符串 | 目标小群 Chat ID；测试阶段可以暂时填写同一个测试群 |
| `sourceSupervisors` | 字符串数组 | 按日报事实表的`直属上级`OpenID筛选；为空表示不按直属上级过滤 |
| `posterSections` | 对象数组 | 海报模块定义，每项包含`key`、`name`、`sourceTargets`、可选的`includeTopics`和`excludeTopics` |

模块匹配规则：先按来源映射确定成员可归属的模块，再按`sourceTargets`和主题关键词匹配；一条日报无法唯一匹配时不强行归类，并记录诊断。只展示至少有一条有效日报事实的模块。AI只生成模块摘要，最终 PNG 由 Node.js 确定性渲染，避免海报文字被图像模型改写。

示例：

```json
{
  "key": "team-b",
  "name": "公司板块",
  "enabled": true,
  "chatId": "oc_test",
  "sourceSupervisors": ["ou_xxx"],
  "posterSections": [
    { "key": "online-hall", "name": "线上营业厅", "sourceTargets": ["线上营业厅项目组"] },
    { "key": "cloud-pay", "name": "云缴费", "sourceTargets": ["对公客群经营及场景建设"], "includeTopics": ["云缴费"] }
  ]
}
```

现有字段迁移：

- 将`周开始日期`重命名为`日报周期开始`。
- 将`周结束日期`重命名为`日报周期结束`。
- 新增`周报日期`。
- 保留已有记录；测试环境可以由脚本重新计算并回填日期字段。

## 飞书电子表格：年度周报工作簿

每年一个工作簿，包含：

- 一个固定模板 Sheet。

模板必须能通过文本动态定位：

| 模块 | 定位路径 | 自动化规则 |
| --- | --- | --- |
| 报告周期 | 报告周期标题右侧 Cell | 写入本周一至本周五，例如`2026年7月27日-7月31日`；不代表 AI 日报读取窗口 |

| 模块二 | 模块标题 + 项目名称 + 下周工作计划 | 保持人工填写 |
| 模块三 | 模块标题 + 板块名称 + 本周工作进展 | 右侧连续三个 Cell，AI 最多写三项 |
| 模块三 | 模块标题 + 板块名称 + 下周工作计划 | 右侧连续三个 Cell，保持人工填写 |

每周复制后：

- 标题为`数字金融部周报MMDD`，其中 MMDD 使用当前周五日期。
- 新 Sheet 移动到第一个 Tab。
